BAGFOOT2

Leslie Cohen

BAGFOOT2 is a computational tool designed to predict which transcription factors (TFs) change their activity between two experimental conditions using ATAC-seq data. BAGFOOT2 is intended for biologists and bioinformaticians interested in chromatin accessibility and transcriptional regulation.

Introduction

Input data:

  • BAM files (aligned ATAC-seq reads)

  • MACS2 output peak files (in BED or narrowPeak format)

Core Methodological Components:

BAGFOOT2 integrates differential accessibility, motif enrichment, and footprinting analysis to infer transcription factor activity changes between two conditions.

Differential accessible regions and motif enrichment: BAGFOOT2 identifies differentially accessible peaks using HOMER and performs motif enrichment analysis on these regions. Enriched motifs are incorporated into the result files.

Footprinting and accessibility quantification. BAGFOOT2 calculates flanking accessibility and transcription factor footprinting metrics from ATAC-seq BAM files, comparing them between the two conditions to detect differential TF activity.

Differential activity scores and visualization Differential scores quantify the change in TF activity between conditions. Results are compiled into a summary table including differential activity values, and statistical significance. BAGFOOT2 also provides a bagplot visualization summarizing differential footprint depth and flanking accessibility, and barplots of the TFs with significant changes, where HOMER-enriched motifs are highlighted.

How Does BAGFOOT2 Work?

Data Processing Steps:

Reads BAM files and identifies accessible chromatin regions using MACS2 peak files.

Calculates chromatin accessibility and TF footprints for each condition.

Computes the difference (delta) in accessibility and footprinting for each TF motif between the two conditions.

Performs HOMER motif enrichment analysis on differentially-accessible regions.

Output Generation:

Produces a results table with TF scores, p-values, and other relevant statistics.

Generates a bagplot for visualizing the distribution and outliers among TF activity changes, and barplots of the TFs with significant changes.

Installation

BAGFOOT2 is distributed through conda. The conda package provides both the bagfoot2 command and the BAGFOOT2 R library used in this vignette:

conda create -n bagfoot2 -c goldsteinlab-tech -c conda-forge -c bioconda bagfoot2
conda activate bagfoot2

System requirements: Linux (or Windows with WSL2), about 16 GB of RAM per core and 20–50 GB of free disk space for the output folder.

Quick start (command line)

The bagfoot2 command runs all the steps described in this vignette with one command line, and produces the final figures and result table:

bagfoot2 \
  --bam_dir    /path/project/bam_merged \
  --peak_dir   /path/project/macs2 \
  --output_dir /path/project/bg_files_fed_fasted \
  --control    fed \
  --treatment  fasted \
  --genome     mm10 \
  --bam_suffix ".sorted.bam" \
  --cores      2

To include HOMER, add --homer TRUE --homer_bin /path/homer/bin --reps_control 1,2,3 --reps_treatment 1,2,3. Run bagfoot2 --help for the full list of options.

The motif database (mm10 or hg38) is downloaded automatically from Zenodo (https://doi.org/10.5281/zenodo.20782782) on first use.

The rest of this vignette describes each step and runs it in R.

BAGFOOT2 Project Environment: Requirements and Structure

Before running BAGFOOT2, you must organize your project files in a specific way to ensure smooth operation and reproducibility. Here’s a detailed guide on setting up your environment.

1. Required Directories

You need to prepare two main directories for each project:

a. Merged BAM Directory

Contains one merged, sorted and indexed BAM file containing all replicas per condition (e.g., treated, control).

Each BAM file should be accompanied by:

Its index file (.bai)

A SAMtools stats file (output from samtools idxstats file.bam > file.bam.csv), named exactly like the BAM file followed by the .csv extension (e.g. fed.sorted.bam.csv).

PCR duplicates must be removed from the BAM files beforehand (e.g. Picard MarkDuplicates).

b. MACS2 Peaks Directory

Contains the MACS2 output files for each condition.

Files must be in BED or narrowPeak format.

Each file should represent the ATAC-seq peaks for a given condition.

2. Additional Requirements (for HOMER Integration)

If you plan to use the HOMER function (highly recommended for advanced analyses):

You must also provide individual BAM files for each replicate within each condition.

These BAM files should:

Be sorted and indexed.

Follow a consistent naming scheme: For example, if your merged BAM is control_suffix.bam, the replicates should be named control_1.bam, control_2.bam, etc.

3. Project Definition

Each project is defined at the beginning of the script (Environment chunk below), specifying:

Project name

Path to merged BAM directory

Path to MACS2 peaks directory

Reference genome version (e.g., mm10, hg38)

Treatments (all_set): List of all conditions (e.g., treated, control)

Couples: Define the pairs of conditions you want to compare (for use in BAGFOOT2)

Important: How to Define “couples” in Your Project File

In the couples section, always list the control condition first, followed by a hyphen (-), then the experimental condition (e.g., control-treated).

Do NOT use underscores (_)!

Pre-processing Overview

Initial Processing and File Generation

This section describes the preprocessing steps required for each condition before downstream analysis.

ATAC-seq signal normalization

Observed vs. Expected Table:

Using the BAM files from ATAC-seq experiments, BAGFOOT2 calculates the observed frequency of each 6-mer at Tn5 insertion sites. It then compares these observed counts to the expected frequencies derived from a genome-wide 6-mer library, generating an observed/expected (O/E) ratio for each 6-mer.

Bias Factor Application:

The O/E ratios serve as bias correction factors to derive expected count per position; observed counts are normalized by these expected counts. BAGFOOT2 applies these factors to adjust the raw ATAC-seq signal, normalizing for sequence bias before any downstream analysis (such as accessibility, footprinting, and delta calculation).

Conceptual Explanation with Annotated Example Code

1. Generate Nucleotide Code Files (Per Chromosome)

For each chromosome in the reference genome (mm9, mm10, hg19, hg38), BAGFOOT2 generates nucleotide code files (nuccode files) that encode the hexamer (6-mer) sequence at each genomic position. These files serve as a lookup table, allowing the pipeline to quickly identify the sequence context at any position during bias correction and footprinting analysis.

This pre-processing step is performed once per genome and is reused across all samples and conditions, ensuring efficient and consistent sequence bias correction throughout the analysis.

2. Generate BedGraph Files

Create a BedGraph file for each condition, representing the genome-wide accessibility profile (Tn5 cut counts).

3. Hexamer Table Construction

For each condition, BAGFOOT2 builds a hexamer (6-mer) bias table that quantifies sequence-dependent Tn5 cutting preferences.

During this step, BAGFOOT2 corrects for the Tn5 transposase offset by shifting the reads (+4 bp for the positive strand, -5 bp for the negative strand), which accurately centers the insertion sites (atac = TRUE).

Using the nuccode files, BAGFOOT2 assigns to each genomic position the local hexamer sequence. The corresponding Tn5 cuts are counted at each position. For every hexamer, BAGFOOT2 then:

  • counts how many times it appears in the genome (GenomicPositionCount), and
  • aggregates the observed Tn5 cuts at all positions carrying this hexamer (ObCuts).

The ratio

      ObCutRatio = ObCuts / GenomicPositionCount

provides an estimate of the cleavage propensity for each hexamer.

The hexamer bias table also includes additional normalization metrics, such as:

  • the genomic proportion of each hexamer among all 6-mers (GPRatio), and
  • a correction factor derived from these quantities.

This correction factor is used in downstream steps to rescale cut counts and remove intrinsic Tn5 sequence bias, ensuring that the resulting footprinting signal reflects true chromatin protection rather than enzymatic preference.

One hexamer bias table is generated per condition. For differential footprinting between two conditions (a couple), BAGFOOT2 later merges the per-condition tables into a combined hexamer file (see summary table), so that both conditions are normalized using the same hexamer set and bias estimates.

This step will produce:

for (treat in all_set) {
  bamfile <- paste0(bam_dir, treat, ".sorted.bam")

  # count the number of cuts in the BAM file
  cc <- countReadsBAM(bamfile, mm)
  print(paste("treat:", treat, "cc:", cc))
  assign(paste0("cc_", treat), cc)

  # The two steps below are the longest of the pre-processing.
  # If their output files already exist (e.g. when the script is run again),
  # they are skipped. To recompute them, delete these files first.
  bedgraph_file <- paste0(bg_dir, treat, "_AC_cutcount.bgr.gz")
  hexamer_file  <- paste0(bg_dir, "Hexamer_", treat, "_", mm, "_withoutMap.txt")

  # generate the BedGraph file of cut counts
  if (!file.exists(bedgraph_file)) {
    cutcountfile <- makeCutCountBAMWithName(bamfile,
                                            name      = basenameWithoutExt(bamfile),
                                            refgenome = mm)
  } else {
    message("BedGraph already exists for ", treat, ": skipped")
  }

  # hexamer bias frequency table (without mappability)
  if (!file.exists(hexamer_file)) {
    MakeBiasCorrectionTableBAM(bamfile   = bamfile,
                               outfile   = paste0("Hexamer_", treat, "_", mm, "_withoutMap.txt"),
                               refgenome = mm,
                               np        = 6,
                               atac      = TRUE,   # Set TRUE for ATAC data. The default value is FALSE
                               mapdir    = "")     # empty: mappability is not used
  } else {
    message("Hexamer table already exists for ", treat, ": skipped")
  }

  # convert MACS2 peaks to CSV
  macs <- read.csv(paste0(macs2_dir, treat, "_peaks.narrowPeak"),
                   sep = "\t", header = FALSE, stringsAsFactors = FALSE)
  names(macs)[1:3] <- c("chr", "st", "ed")
  nr <- nrow(macs)

  hotspot <- data.frame(ID = 1:nr, chrom. = macs$chr, start = macs$st + 1, end = macs$ed,
                        MaxD   = rep(0, nr),
                        AveD   = rep(0, nr),
                        Zscore = rep(0, nr),
                        pvalue = rep(0, nr))

  write.table(hotspot, file = paste0(bg_dir, treat, "_peaks.csv"), sep = ",", row.names = FALSE)
}

HOMER Integration: Differential ATAC-seq and Motif Enrichment

Run HOMER

To use this part of the workflow with BAGFOOT2, it is essential to have HOMER installed on your system, following the official recommendations provided on the HOMER installation page:

http://homer.ucsd.edu/homer/introduction/install.html

Please make sure to carefully follow the instructions on the official HOMER website to ensure a correct installation and full access to all required features.

With BAGFOOT2, it is highly recommended to run HOMER to perform motif analysis on differentially accessible ATAC-seq peaks.

Integrating HOMER allows you to identify transcription factor motifs that are enriched in regions showing differential accessibility between conditions.

In this chunk, the workflow proceeds as follows:

  • Load the peak files and all BAM files for each replicate within every condition.

  • Use HOMER to count the number of tags per peak for each replicate.

  • Normalize these counts across replicates and conditions.

  • Perform differential analysis with DESeq2 via HOMER, generating an annotated file of differentially accessible peaks.

  • For these differential peaks, run motif enrichment analysis with HOMER.

The results of the motif enrichment analysis are displayed as gold rings in BAGFOOT2’s bagplot and labelled “ME” in the barplots. In addition, HOMER motif enrichment appears in the BAGFOOT2 output table.

The number of replicates can differ between conditions (e.g. 3 and 2). If the HOMER results of a couple already exist (homer_motif_res_<control>_<treatment>/knownResults.txt), HOMER is skipped for this couple.

setwd(bg_dir)

# ==============================================================================
# USER SETTINGS (HOMER): edit the lines marked with  # <-- EDIT
# ==============================================================================

use_homer <- TRUE                                    # <-- EDIT: FALSE to skip HOMER

homer_bin <- "/path/to/homer/bin/"    # <-- EDIT: HOMER bin directory

# replicate indices of each condition (the numbers can differ, e.g. 1:3 and 1:2)
reps_control   <- 1:3   # <-- EDIT: fed_1.bam, fed_2.bam, fed_3.bam
reps_treatment <- 1:3   # <-- EDIT: fasted_1.bam, fasted_2.bam, fasted_3.bam

# thresholds to select the differential peaks
padj_cutoff <- 0.05     # <-- EDIT (optional): adjusted p-value
l2fc_cutoff <- 0.5      # <-- EDIT (optional): |log2 fold change|

# ==============================================================================
# END OF USER SETTINGS (no change needed below)
# ==============================================================================

# directory containing the replicate BAM files
work_dir <- bam_dir

if (use_homer) {
  for (c in couples) {
    set1 <- str_split_fixed(c, "-", 2)[1]   # control
    set2 <- str_split_fixed(c, "-", 2)[2]   # treatment

    output_folder <- paste0(bg_dir, "homer_motif_res_", set1, "_", set2)
    if (file.exists(file.path(output_folder, "knownResults.txt"))) {
      message("HOMER results already exist for ", c, ": skipped")
      next
    }

    # output files
    annotate_outfile <- file.path(bg_dir, paste0(set1, "_", set2, "_annot.txt"))    # annotatePeaks.pl
    diffexp_outfile  <- file.path(bg_dir, paste0(set1, "_", set2, "_output.txt"))   # getDiffExpression.pl

    # groups for getDiffExpression.pl: one label per replicate
    group1 <- rep(set1, length(reps_control))     # control
    group2 <- rep(set2, length(reps_treatment))   # treatment

    # convert the merged peak file to the HOMER format
    input_file1  <- file.path(bg_dir, paste0("pooled_", set1, "_", set2, "_hotspot.csv"))
    output_file1 <- file.path(bg_dir, paste0("pooled_", set1, "_", set2, "_hotspot_modify.txt"))

    process_hotspot_file(
      input_file1,
      output_file1
    )

    # 1. create one tag directory per replicate (in the BAM directory), only for this couple
    #    can take more than 30 min
    td_dirs <- c()
    for (cond in c(set1, set2)) {
      reps <- if (cond == set1) reps_control else reps_treatment
      for (i in reps) {
        bam_rep <- file.path(work_dir, paste0(cond, "_", i, ".bam"))
        td_dir  <- file.path(work_dir, paste0("TD_", cond, "_", i))
        if (!file.exists(bam_rep)) stop("Replicate BAM not found: ", bam_rep)
        if (!dir.exists(td_dir)) {
          system(paste(file.path(homer_bin, "makeTagDirectory"), td_dir, bam_rep, "-format sam"))
        } else {
          message("Tag directory already exists: ", basename(td_dir))
        }
        td_dirs <- c(td_dirs, td_dir)
      }
    }

    # 2. count tags per peak (annotatePeaks.pl)
    run_annotate_peak(homer_bin, work_dir, output_file1, mm, td_dirs, annotate_outfile)

    # 3. differential analysis (getDiffExpression.pl, DESeq2)
    run_diff_expression(
      homer_bin,
      work_dir,
      annotate_outfile,
      diffexp_outfile,
      group1,
      group2
    )

    # 4. keep differential peaks only: BED file + table with log2FC, padj and p-value
    setwd(bg_dir)   # important: the files are created in the working directory
    diff_prefix <- paste0(set1, "_", set2, "_diff_peaks")
    create_diff_peak_files(
      input_path     = bg_dir,
      input_filename = basename(diffexp_outfile),
      sep            = "\t",
      chr            = "Chr",
      start          = "Start",
      end            = "End",
      padj_cutoff    = padj_cutoff,
      l2fc_cutoff    = l2fc_cutoff,
      output_prefix  = diff_prefix
    )

    # 5. motif enrichment on the differential peaks (findMotifsGenome.pl)
    #    can take more than 30 min
    input_bed   <- paste0(bg_dir, diff_prefix, "_simple.bed")
    homer_exe   <- file.path(homer_bin, "findMotifsGenome.pl")
    motif_file  <- system.file("data", "all_cluster_motifs.motifs", package = "bagfoot2")
    extra_args1 <- paste("-mknown", motif_file, "-p", numcores)

    run_homer(
      input_bed,
      output_folder,
      mm,
      homer_exe,
      extra_args1
    )
  }
}

BAGFOOT2 Processing: Footprinting and TF Activity Inference

In the final step, BAGFOOT2 integrates all precomputed inputs to quantify transcription factor (TF) activity differences between conditions. For each condition pair, BAGFOOT2 performs sequence-bias–corrected footprinting over all genomic motif occurrences and summarizes the results using a bagplot and barplots.

Input objects

For each condition, a CutCount object is created from the ATAC-seq BedGraph file (*_AC_cutcount.bgr.gz).

These objects store the Tn5 cut profiles and are used as the control and treatment signals in the footprinting & flanking accessibility analysis.

In addition, BAGFOOT2 loads:

  • MotifDB : archetype motif occurrence coordinates derived from a FIMO genome-wide scan. These files (mm10_files.tar.gz, hg38_files.tar.gz) are available here: https://doi.org/10.5281/zenodo.20782782, and can be downloaded automatically with ensure_motif_db().

  • Merged hexamer bias table (Hexamer_set1_set2_merged_withoutMap.csv): used for sequence-bias correction.

  • Pooled hotspot file (pooled_set1_set2_hotspot.csv): merged peak regions defining the common universe of sites where footprint are calculated.

Running BAGFOOT2 by motif batches

For each couple of conditions (e.g., fed vs fasted), BAGFOOT2 constructs a GFootOption object specifying:

  • the merged hexamer bias file, and

  • the hexamer index pattern (nuccode_{genome}_6mer_{chr}.dat).

The nuccode files are generated automatically during the pre-processing step (hexamer table construction).

The main footprinting routine is performed with the GFoot() function:

  • control and treatment correspond to the two CutCount objects,

  • sitefile points to the pooled hotspot file (merged peaks),

  • motifDB provides genomic coordinates of archetype motif occurrences,

  • gfootoption controls bias correction and hexamer handling,

  • outputdir and cachedir store intermediate and final results.

To make the computation efficient, motifs are processed in batches of 25. The script automatically detects any existing *_footprint_depth_table.csv files and resumes from the next motif index if a previous run was interrupted. This restart mechanism is driven by the start_motif variable.

The run() function applies GFoot to all motifs in the specified range, using:

  • mc.cores to parallelize over CPU cores,

  • graphout = TRUE to generate footprint plots,

  • yrange to harmonize the y-axis scale across motifs.

Flanking and central accessibility

For each motif occurrence, BAGFOOT2 quantifies:

  • central accessibility: Tn5 cuts over the motif core, where a footprint may appear, and

  • flanking accessibility: Tn5 cuts in the surrounding regions, providing a local background reference.

These signals are integrated into three log2 ratios (treatment vs control):

  • lrmotif — accessibility change at the motif center,

  • lrflanking — accessibility change in the surrounding regions,

  • lrtotal — combined statistic (motif + flanks), used to assess TF activity shifts.

This flanking-versus-center framework ensures that footprint depth reflects true binding-dependent protection rather than broader chromatin accessibility changes.

Merging footprint tables

Each batch produces a separate *_footprint_depth_table.csv file.

After all batches are completed, these files are concatenated into a single merged table:

  • *_hotspot_footprint_depth_table_leslie_merged.csv

This table contains, for each motif:

  • footprint depths in control and treatment (fdepth1, fdepth2),

  • mean cut counts (meancc1, meancc2),

  • log2 ratios derived from central and flanking accessibility (lrmotif, lrflanking, lrtotal),

  • the number of motif sites used (numsite).

Visualization and integration with HOMER

To summarize TF activity changes, BAGFOOT2 calls gen_bagplot_bagfoot2() function. This step:

  • generates a bagplot, where each point corresponds to a motif/TF,

  • highlights motifs with significant differential footprinting (based on q-values),

  • generates barplots of the TFs with significant changes (FDR below the threshold and outside the bagplot fence), one panel for increased and one for decreased activity in the treatment,

  • optionally annotates motifs using HOMER motif enrichment results based on archetype motifs (knownResults.txt), allowing the user to cross-reference footprint-based activity changes with motif enrichment p-values.

The following files are generated, providing an overview of TFs that gain or lose activity between the two conditions:

  • the bagplot (*_bfoot2.pdf and *_bfoot2_zoomIn.pdf),

  • the barplots of the significant TFs, ranked by D2 (*_maha_D2.pdf / .tiff) and by FDR (*_maha_padj.pdf / .tiff),

  • the CSV result table with all values for each motif (*_bagfoot2_output.csv).

Note: dataname1 must be the treatment and dataname2 the control, so that the “increase” panel corresponds to the treatment.

Finally, sessionInfo() is printed to record the R environment and package versions used in the analysis, ensuring full reproducibility of the BAGFOOT2 run.

  # restart: find the batches already done
  output_files <- list.files(bg_dir,
                             pattern   = glob2rx(paste0(set1, "_", set2, "_On_pooled_", set1, "_", set2,
                                                        "_hotspot_footprint_depth_table", ".csv")),
                             recursive = TRUE)
  if (length(output_files) == 0) {
    start_motif <- 1
  } else {
    # starting motif = last batch done (from the folder name) + 25
    start_motif <- dirname(output_files) %>%                  # directory name
      str_split(., "\\_", simplify = TRUE) %>%                # split by underscore
      as.data.frame(stringsAsFactors = FALSE) %>%
      dplyr::select(tail(names(.), 1)) %>%                     # keep the last column
      mutate_if(is.character, as.numeric) %>%                  # convert to numeric
      max + 25                                                 # last batch + 25
  }

  # footprinting by batches of 25 motifs
  if (start_motif < motif_no) {
    for (r in seq(start_motif, motif_no, by = 25)) {
      print(paste("r ---------------------->", r))
      GFoot_obj <- GFoot(control     = get(set1),                                         # control data
                         treatment   = get(set2),                                         # treatment data
                         sitefile    = paste0("pooled_", set1, "_", set2, "_hotspot.csv"),   # combined peaks
                         motifDB     = motifdb_mm,                                        # FIMO motifs
                         gfootoption = gfootoption_couple,                                # bias and hexamer files
                         outputdir   = paste0("OUTPUT_", c, "_", r),                      # output directory
                         cachedir    = paste0("CACHE_", c, "_", r))                       # cache directory

      res_couple <- run(GFoot_obj, graphout = TRUE, yrange = c(-2.2, 1.0), mc.cores = numcores,
                        range = r:min(r + 24, motif_no), run_set = c)
      gc()   # garbage collector
    }
  }

  # merge the footprint tables of all batches (without header line)
  setwd(bg_dir)
  merge_output_leslie <- paste0("find . -type f -name '",
                                set1, "_", set2, "_On_pooled_", set1, "_", set2,
                                "_hotspot_footprint_depth_table.csv' -exec tail -n +2 -q {} ';'",
                                " > ", set1, "_", set2, "_On_pooled_",
                                set1, "_", set2, "_hotspot_footprint_depth_table_leslie_merged.csv")
  system(merge_output_leslie)

  # read the merged table and add the header
  dat_leslie <- read.table(paste0(bg_dir, set1, "_", set2, "_On_pooled_", set1, "_", set2,
                                  "_hotspot_footprint_depth_table_leslie_merged.csv"),
                           quote = "\"", comment.char = "")
  colnames(dat_leslie) <- c("num", "filename", "center", "logo", "motiflength", "motif", "memeNo", "memeEntry",
                            "lrmotif", "lrflanking", "lrtotal", "fdepth1", "fdepth2", "meancc1", "meancc2", "numsite")

  # bagplot + barplots + CSV table with all values
  # NOTE: dataname1 = treatment, dataname2 = control (we plot treatment vs control)
  test_gen <- gen_bagplot_bagfoot2(
    dat_leslie,
    dataname1               = set2,   # treatment -> "increase" panel
    dataname2               = set1,   # control   -> "decrease" panel
    qvaluethreshold_bagplot = 0.05,
    factor                  = 1.5,
    include_homer_results   = use_homer_results,   # TRUE only if HOMER results exist
    homer_results_file      = homer_results_file,
    pval_threshold_homer    = 0.05
  )
}
